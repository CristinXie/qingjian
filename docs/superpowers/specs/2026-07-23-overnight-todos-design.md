# 桌面待办跨天功能设计

## 目标

支持在桌面待办组件中创建和编辑跨越午夜的时间范围待办，同时保持现有日期视图、排序和持久化结构稳定。

## 范围

本功能覆盖桌面待办的新增、编辑、服务层校验、时间显示、日期归属和相关自动化测试。它不支持跨越多天的待办，不新增提醒功能，也不增加独立的结束日期选择器。

## 时间规则

待办继续使用现有的 `Date`、`StartTime` 和 `EndTime`：

- `Date` 始终表示起始日期。
- 只填写开始时间时，待办仍为单时间待办。
- 同时填写开始和结束时间，且开始时间早于结束时间时，待办为当天时间范围。
- 同时填写开始和结束时间，且开始时间晚于结束时间时，待办为跨天时间范围；开始时间属于 `Date`，结束时间属于 `Date.AddDays(1)`。
- 开始时间等于结束时间时判定为无效，不解释为零时长，也不解释为24小时。
- 只填写结束时间、只填写时间点的一部分或输入超出有效时分范围时，继续判定为无效。

跨天待办的结束日期固定为次日。由于相同时间无效，任何可保存的跨天待办持续时间均大于0且小于24小时，满足最多跨越24小时的限制。

## 数据设计

采用从现有时间字段推导跨天状态的方案，不新增 `IsOvernight` 或结束日期字段，也不修改数据库结构：

- `StartTime < EndTime`：当天范围。
- `StartTime > EndTime`：跨天范围。
- `StartTime == EndTime`：无效范围。

应用内新增统一的时间范围判断逻辑，供草稿解析、服务层校验和显示转换器共同使用。避免 UI 接受某个范围、服务层拒绝或显示层误判。

## 交互与显示

新增和编辑浮窗继续使用现有的开始小时、开始分钟、结束小时和结束分钟输入框，不增加跨天开关或日期输入。

- 输入晚于结束时间的开始时间后，保存时自动识别为跨天待办。
- 相同起止时间继续显示 `时间选择不规范`。
- 编辑已有跨天待办时直接回填原有起止时间，保存后按同一规则重新判断。
- 当天范围继续显示为 `09:30-10:45`。
- 跨天范围显示为 `23:00-次日 01:00`。
- 无时间和单时间待办的显示保持不变。

## 日期归属、查询和排序

跨天待办只归属于起始日期：

- 八日视图、今日视图、月历日期单元格、管理浮窗和日历预览均只在 `TodoItem.Date` 对应日期显示该待办。
- 次日不重复显示跨天待办。
- 数据库日期范围查询继续使用 `TodoItem.Date`。
- 日期内排序继续按起始时间排序；跨天属性不改变完成状态和无时间待办的现有排序规则。
- 所有当前及未来按日期统计待办数量的逻辑都以 `TodoItem.Date` 为准，即以跨天待办的起始日期为准。

## 服务层保护

UI 草稿解析器负责即时输入校验，服务层继续执行相同的二次校验：

- 当天范围和跨天范围都可创建、更新。
- 相同起止时间、不完整范围和缺少必需时间的草稿被拒绝。
- 无时间和单时间草稿的规范化行为保持不变。

## 测试

自动化测试至少覆盖：

- 快速新增分别接受当天范围和跨天范围。
- 快速新增拒绝相同起止时间、只填结束时间和不完整时间点。
- 服务层创建和更新接受跨天范围，并保留起始日期。
- 服务层拒绝相同起止时间。
- 跨天判断和持续时间不超过24小时。
- 时间转换器为跨天范围添加 `次日`，当天、单时间和无时间显示保持不变。
- 日期筛选和排序继续按起始日期及起始时间处理跨天待办。
- 完整 Release 测试和 Release 构建通过。

## 不在本次范围

- 跨越两天以上的待办。
- 显式选择结束日期。
- 恰好24小时的时间范围。
- 在结束日期重复展示跨天待办。
- 跨天提醒、通知或进度展示。
