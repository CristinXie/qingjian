# QingJian 文件夹功能设计

日期：2026-07-24  
分支：`feature/ui-polish`

## 目标

为主窗口增加可靠的单层文件夹管理能力。每条便签只能属于一个文件夹，用户可以创建、重命名和删除文件夹，按文件夹筛选便签，并从便签卡片直接改变所属文件夹。

本功能沿用现有 `Note.FolderName` 字段，优先保证旧数据库兼容和低风险升级。

## 范围

本次包含：

1. 单层、单归属文件夹模型。
2. 独立的文件夹管理窗口。
3. 创建、重命名、删除文件夹。
4. 按文件夹筛选主窗口便签。
5. 从便签卡片移动单条便签。
6. 在当前文件夹中新建便签时自动归入该文件夹。
7. 文件夹筛选与现有搜索、收藏排序、时间排序及日期分组组合工作。
8. 文件夹操作失败时的事务保护、内存回滚和中文提示。

本次不包含：

1. 子文件夹或任意层级目录。
2. 一条便签归入多个文件夹。
3. 文件夹手动拖拽排序。
4. 批量移动便签；“批量管理”按钮继续保持空实现。
5. 快捷便签中的文件夹选择；快捷便签保存后仍进入“未分类”。
6. 跨重启保存当前文件夹筛选状态。

## 数据模型

### Folder

新增 `Folder` 实体和 `Folders` 表，至少包含：

- `Id`：稳定的字符串 ID。
- `Name`：显示名称。
- `NormalizedName`：用于不区分大小写判重的规范化名称。
- `CreatedAt`：创建时间。
- `IsSystem`：是否为系统文件夹。

“未分类”是固定系统文件夹，始终存在，不允许重命名或删除，但可以正常查看，也可以把便签移入或移出。其余文件夹按名称升序显示。“全部便签”只是主窗口筛选状态，不保存为文件夹记录。

### Note 归属

继续使用现有 `Note.FolderName` 保存归属，不在本次引入 `FolderId` 外键。文件夹存储承担注册表职责，使没有便签的空文件夹也能长期存在。

数据库初始化必须：

1. 以幂等方式创建 `Folders` 表和名称唯一索引。
2. 补齐“未分类”系统文件夹。
3. 扫描现有便签中的非空 `FolderName`，将尚未注册的名称补录为普通文件夹。
4. 继续把空白或等于保留名称“全部便签”的旧归属修正为“未分类”。
5. 对旧名称去除首尾空格；名称仅大小写不同的旧记录合并到同一个规范名称，并同步统一便签上的显示名称。

旧数据中超过 30 个 Unicode 文本元素的名称原样保留，避免升级时截断用户数据；此后必须先重命名为合法名称，界面才允许继续使用该名称作为移动目标。

旧数据库升级不删除或改写现有 `FolderName` 列。

## 名称规则

文件夹名称统一在服务层校验和规范化：

1. 去除首尾空格。
2. 不能为空。
3. 最多 30 个 Unicode 文本元素。
4. 名称不区分大小写且不能重复。
5. 禁止普通文件夹使用“全部便签”和“未分类”。

`NormalizedName` 由经过 Unicode 兼容性规范化的名称执行 invariant uppercase 得到，数据库唯一索引与服务层使用同一结果，避免两套判重规则。

界面层可以即时显示校验结果，但不能成为唯一校验位置。

## 架构

新增独立的文件夹持久化和业务边界：

- `IFolderRepository` / `FolderRepository`：查询文件夹、创建记录，以及事务化重命名和删除。
- `FolderService`：名称校验、系统文件夹保护、排序和面向 UI 的操作。
- `FolderManagementViewModel`：管理窗口状态、行内编辑和命令。
- `FolderManagementWindow`：独立 WPF 窗口，仅负责展示和交互转发。

`NoteService` 增加创建到指定文件夹及移动单条便签的能力。移动失败时必须恢复 `Note.FolderName` 的原值。

`MainViewModel` 负责当前文件夹筛选、文件夹与搜索组合过滤、移动后的选择恢复以及导航刷新。文件夹管理逻辑不得堆入 `MainWindow` 代码后置文件。

## 持久化操作

### 创建

创建普通文件夹时保存规范化名称并依赖数据库唯一约束兜底。创建成功后空文件夹立即出现在管理窗口和便签文件夹菜单中。

### 重命名

重命名必须在同一 SQLite 事务中：

1. 校验目标名称。
2. 更新文件夹记录。
3. 更新所有引用旧名称的便签，包括已软删除便签，以保持数据一致。

若被重命名的是当前筛选文件夹，主窗口同步跟随新名称，不退出筛选。

### 删除

删除普通文件夹必须在同一 SQLite 事务中：

1. 将所有引用该名称的便签改为“未分类”。
2. 删除文件夹记录。

删除当前筛选文件夹后，主窗口切换到“未分类”。软删除便签不计入界面显示的便签数量，但数据库迁移仍覆盖它们。

### 移动便签

移动便签只更新其 `FolderName`，不改变 `UpdatedAt`，避免文件夹整理无意改变按最后修改时间排序的结果。移动失败时恢复内存值并保持当前筛选和选择不变。

## 文件夹管理窗口

点击主窗口左下角现有“文件夹”图标，打开一个由主窗口拥有的独立管理窗口。

窗口内容：

1. 顶部提供无边框、无按钮格底色的新增图标按钮，悬浮提示“新建文件夹”。
2. “全部便签”固定入口，显示全部未删除便签数量。
3. “未分类”固定在普通文件夹之前。
4. 其他文件夹按名称升序排列。
5. 每行显示文件夹图标、名称和未删除便签数量。
6. 普通文件夹右侧显示无边框、无按钮格底色的重命名和删除图标按钮。
7. 所有图标按钮使用即时中文悬浮提示。
8. “未分类”不显示重命名和删除操作。

点击“全部便签”或任意文件夹行会关闭窗口并把对应筛选应用到主窗口。点击行内操作按钮不得触发行选择。

新建和重命名在管理窗口内行内完成，使用确认和取消图标按钮。输入无效时保留编辑状态并显示中文原因。

删除任何普通文件夹都需要确认。若文件夹包含便签，提示文字必须明确说明“其中 X 条便签将移至未分类”；空文件夹也需要确认。

## 主窗口筛选

主窗口增加可空的当前文件夹筛选状态：

- 无筛选表示“全部便签”。
- 有筛选时，搜索框下方显示文件夹图标、当前文件夹名称和清除筛选图标。
- 清除图标返回“全部便签”。
- 搜索仅匹配当前文件夹中的便签。
- 收藏/时间排序和现有分组规则保持不变。
- 应区分“当前文件夹为空”和“搜索无结果”两种空状态。

应用一个不包含当前选中便签的筛选前，先保存编辑器中的最新正文，再选择筛选结果中的第一条便签。清除筛选时，若原选中便签仍可见则保持选择。

## 便签归属交互

便签卡片第三行现有“文件夹图标 + 文件夹名”改为可点击的无边框区域。点击后弹出选择菜单：

1. 显示“未分类”和全部普通文件夹，普通文件夹按名称升序排列。
2. 当前所属文件夹显示选中标记。
3. 菜单底部提供“新建文件夹…”。
4. 从菜单创建文件夹成功后，当前便签立即移动到新文件夹。

“新建文件夹…”打开一个由主窗口拥有的轻量名称输入对话框；确认成功后关闭对话框并完成移动，取消或校验失败时不改变便签归属。

在某个文件夹筛选中把便签移到其他文件夹后，该便签立即从列表消失，并选择原位置之后的下一条可见便签；没有下一条时选择上一条；列表为空时进入文件夹空状态。

若移动的是当前正在编辑的便签，必须先从 WebView 拉取最新 Markdown 并保存，再更新文件夹归属和选择。

## 新建便签

- 当前筛选某个文件夹时，主窗口“新建便签”创建到该文件夹。
- 当前显示“全部便签”时，新便签进入“未分类”。
- 快捷便签继续进入“未分类”，本次不增加额外控件。

## 自动保存保护

文件夹筛选和移动会增加选择切换频率，因此同时修正自动保存目标的捕获方式：延迟保存任务必须捕获实际触发修改的 `Note` 实例，不能在延迟结束后重新读取可能已经变化的 `SelectedNote`。

从管理窗口应用筛选、清除会导致选择变化的筛选，以及移动当前便签前，主窗口都必须先拉取编辑器最新内容并完成即时保存。

## 错误处理与同步

- 创建、重命名、删除和移动失败时显示具体中文错误。
- 失败操作不得关闭管理窗口、改变当前筛选或留下部分数据库更新。
- 事务失败必须回滚数据库；已修改的界面模型必须恢复原值。
- 文件夹管理窗口每次打开时读取最新文件夹和计数。
- 成功操作后同步刷新主窗口文件夹菜单、卡片归属、筛选名称和列表结果。
- 首次启动和每次重启默认进入“全部便签”。

## 测试与验收

### 数据与服务测试

1. 新数据库创建文件夹表和系统文件夹。
2. 旧数据库升级并补录现有 `FolderName`。
3. 重复初始化保持幂等。
4. 重命名同步更新所有便签。
5. 删除后便签全部移入“未分类”。
6. 事务中途失败不会产生部分更新。
7. 名称空白、超长、重复、保留名称和系统文件夹操作均被拒绝。
8. 单条移动失败恢复内存归属。

### ViewModel 与 UI 测试

1. 文件夹筛选与搜索、收藏排序、时间排序正确组合。
2. 当前文件夹中新建便签使用正确归属。
3. 移出当前筛选后按规则选择下一条或进入空状态。
4. 重命名和删除当前筛选后状态正确。
5. 自动保存始终保存实际被修改的便签。
6. 管理窗口包含约定控件、行内编辑、即时中文工具提示和无边框图标按钮。
7. 卡片文件夹区域、选择菜单和筛选条符合约定。
8. 快捷便签仍默认保存到“未分类”。
